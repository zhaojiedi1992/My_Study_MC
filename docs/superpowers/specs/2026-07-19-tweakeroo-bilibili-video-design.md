# Tweakeroo B 站视频包设计

**日期：** 2026-07-19

**状态：** A 方案已确认，待书面复核

## 1. 目标

基于已经确认的 Tweakeroo PC 演示页和十张真实游戏截图，制作一条约 3 分 20 秒的中文 B 站视频。视频不复述完整配置菜单，只讲五项有明确使用场景、容易让普通玩家立刻理解价值的客户端能力：

1. 灵魂出窍；
2. 自动切换鞘翅与胸甲；
3. 自动补货；
4. 快速左键与快速右键；
5. Gamma 亮度修改。

视频采用用户确认的 **A 方案：痛点反转型叙事**。前 8 秒先连续展示三个结果，再用“遇到什么麻烦 → 开什么功能 → 能省掉什么操作”的结构讲解。吸引点击依靠明确收益和真实反差，不虚构功能，不使用与内容不符的夸张承诺。

视频同时服务三个转化目标：

- **提高完播：** 开头直接给出灵魂出窍、自动补货和 Gamma 的结果，随后每 20–30 秒更换一个能力。
- **促进收藏：** 五项能力组成可回查的设置清单，简介、章节和置顶评论提供相同索引。
- **促进关注：** 开场建立“这里不念配置表，只把复杂模组翻译成能直接使用的场景”这一账号承诺；结尾再次兑现同一价值，让关注理由从一句口号变成观众能预期的长期内容。

## 2. 受众、语气与边界

- 受众是会安装 Fabric 模组、知道基本游戏操作，但没有系统使用 Tweakeroo 的 Minecraft Java 版玩家。
- 画面只考虑 PC 横屏视频，输出 1920×1080，不新增移动端演示适配。
- 旁白采用自然、略年轻的中文男声，语气轻松、有少量干净吐槽，但不使用连续网络梗、尖叫、播音腔或故意油腻的语调。
- 每项能力最多安排一个笑点，笑点必须帮助记忆正确边界，例如“洞是亮了，刷怪规则并没有被你说服”。
- Tweakeroo 是客户端模组；多人服务器规则始终优先。快速点击、自动操作等能力只介绍正常用途，明确使用前应先阅读服务器规则。
- 灵魂出窍只描述为视角离开本体、方便观察和检查，不暗示穿墙获取不应获得的信息，也不包装为服务器规避工具。
- Gamma 只改变客户端画面的可见度，不改变真实光照、刷怪条件或服务器规则。
- 本视频不详细讲 Litematica、MiniHUD、Item Scroller 已承担的放置、投影、HUD 和库存滚动能力。

## 3. 核心包装

### 推荐标题

`Tweakeroo 不只会灵魂出窍！自动补货、换胸甲这 5 个功能真省事`

标题先用玩家熟悉的“灵魂出窍”建立识别，再给出自动补货、换胸甲两个具体收益，避免只有 `X + C` 这类圈内快捷键才能理解。发布资料同时提供两条可替换标题，便于发布前按封面效果选择：

- `装了 Tweakeroo 还在手动补方块？这 5 个功能真的能省事`
- `别把 Tweakeroo 只当配置菜单！5 个高频功能一次讲明白`

### 封面文案

- 主标题两行：`别再` / `手动了！`
- 品牌徽标：`Tweakeroo · 5 个高频功能`
- 三个收益短签：`自动补货`、`快速换甲`、`矿洞提亮`

标题和封面不重复同一句话：标题负责“这是哪个模组、能解决什么”，封面只负责在信息流里制造一个一眼能懂的痛点。封面以真实游戏截图为主体，最多使用两张图片。灵魂出窍画面裁近玩家本体，负责角色记忆点；Gamma 开启画面提供青蓝色块和明暗反差。允许为封面构图裁切图片，但不伪造游戏 UI 或不存在的效果，也不得拼成难以辨认的九宫格。

标题使用白色、青色和暖黄色，整体延续演示页的深蓝青玻璃风格。人物、主标题和 `Tweakeroo` 三者构成唯一视觉层级，收益短签属于次要信息。输出前必须把封面缩小到约 320×200 和 320×240 检查：主标题、模组名和人物仍能识别，收益短签看不清也不能影响核心信息。最终输出 1600×1000 和 1600×1200 两种比例，并保留 PNG 与高质量 JPG。

## 5. 镜头与画面设计

### 单一画面来源

`source/MOD介绍/tweakeroo/index.html` 是视频静帧的视觉来源。制作脚本只使用其 `export=1&slide=N&state=...` 确定性状态，不复制另一套幻灯片内容。十张原始 PNG 不改名、不覆盖、不降采样。

视频使用以下状态：

- 灵魂出窍：`slide=2&state=config`、`slide=2&state=effect`
- 鞘翅与胸甲：`slide=3&state=auto`、`slide=3&state=chestplate`
- 自动补货：`slide=4&state=config`、`slide=4&state=threshold`、`slide=4&state=done`
- 快速点击：`slide=5&state=left`、`slide=5&state=right`
- Gamma：`slide=6&state=config`、`slide=6&state=off`、`slide=6&state=on`
- 快速上手与安装：`slide=7`、`slide=8`

### 图片完整性与动画

- 默认镜头使用演示页中的 `object-fit: contain` 构图，完整等比显示原图，不把 16:10 截图强裁成 16:9。
- 配置页只在讲到目标设置行时使用已有的局部聚焦状态；聚焦前至少保留一个完整画面建立位置关系。
- 实机效果图采用 1.00–1.045 倍的慢速推拉，不做持续晃动、旋转或高频缩放。
- 章节切换使用 0.25 秒交叉淡化，并配低强度点击提示音；不使用来源不明的背景音乐。
- 前 8 秒允许更快的 2.75–3 秒切换，但每个结果必须能看清，不使用闪白或遮挡主体的大字动画。
- 字幕和标注放在安全区，不遮挡配置行、准星、快捷栏或 Gamma 明暗对比的关键区域。

### 转粉结构与旁白语感

旁白不是功能说明书。开头先展示账号的内容筛选能力，中段用具体场景兑现，结尾再把这种筛选能力变成关注理由。全片只保留两个明确 CTA：结尾的收藏和关注；中段不突然打断内容求三连。

以下句子确定语气和账号承诺，最终旁白以完整分镜稿为准：

- 开场：“还在手动补方块、换胸甲？Tweakeroo 里这五个功能，专门负责让手指少加几次班。”
- 账号承诺：“这里不念配置表。只挑真正能用上的场景，把几十页设置翻译成人话。”
- 灵魂出窍：“人留在原地，视角出去转一圈。看建筑、查路线，都不用本人跑过去加班。”
- 自动补货：“手里还剩六个，背包里的同类方块就来接班，建筑节奏终于不用反复开背包。”
- 快速点击：“左键和右键各管各的；能少按几次，但别在多人服里把它当机关枪。”
- Gamma：“矿洞是亮了，刷怪规则并没有被你说服，该插的火把还是得插。”
- 结尾：“关注我。以后装一个模组，不用再自己翻几十页菜单，我继续帮你挑真正省事的那几个。”

## 6. 配音、字幕与声音

- 首选 `zh-CN-YunxiNeural`：现有语音列表将其标为 `Novel / Lively, Sunshine`，比偏新闻播报的 `Yunyang` 更适合轻松口语。回退顺序为 `Yunyang`、`Yunjian`，不得静默换成不同性别的声音。
- 默认语速约 `-2%`，音高保持 `0Hz`。明显降调会强化电子处理感，因此只在实际试听证明必要时轻微调整，不为了“低沉男声”牺牲自然度。
- 旁白按口语呼吸重写：单句通常 8–22 个汉字，一个句子只表达一个动作或结论；少用书面并列、括号、连续专有名词和“首先、其次、最后”。
- 每个镜头按语义短句独立生成，使用标点和 120–420 毫秒的可控间隔形成自然停顿；不把整段文字一次交给 TTS 后依赖机器自行断句。
- 正式全量配音前生成约 25 秒的 `voice-preview.mp3`，内容必须同时包含冷开场、普通讲解和 Gamma 笑点。用户试听确认语速、重音、断句和笑点像正常说话后，才沿用相同声音参数生成全片。
- 每个镜头保留原始时间字幕。最终时间轴以实际音频长度为依据，镜头尾部保留 0.25–0.9 秒呼吸空间。
- 字幕为简体中文，每屏最多两行，每行最多约 18 个字符；英文标识如 `Tweakeroo`、`Gamma`、`MaLiLib` 不得从中间断开。
- 交付独立 SRT 和烧录字幕发布版。烧录字幕使用高对比白字、深色细描边，1080p 成片的视觉字号不低于约 42 px。
- 最终人声目标综合响度约 `-16 LUFS`，真峰值不高于 `-1 dBTP`。干净母版与字幕版使用相同的已归一化音轨。
- 另导出语音试听片段和一条完整独立配音文件，便于复核或重新剪辑。

## 7. 发布资料

发布资料统一由实际分镜时间线生成，包含：

1. 推荐标题和两条备选标题；
2. 两段式简介，第一段给收益，第二段交代版本与多人边界；
3. 自动同步的章节时间轴；
4. 标签：`Minecraft`、`我的世界`、`Tweakeroo`、`Fabric`、`MaLiLib`、`模组推荐`、`生存技巧`、`建筑辅助`；
5. 置顶评论，包含五项能力索引、收藏提示和一个具体互动问题：“这五个里面，你原来完全没用过的是哪一个？”；
6. 封面文案和上传文件选择说明。

简介明确：演示基于 Minecraft Java 版 26.2、Tweakeroo 26.2-0.29.2 与 MaLiLib 0.29.2；不同版本的菜单、名称和行为可能变化，实际应使用与游戏版本匹配的文件。

## 8. 制作架构与文件边界

新建独立包 `scripts/tweakeroo_video/`，不修改当前有未提交改动的 `scripts/minihud_video/` 文件。分镜是单一事实来源，统一驱动静帧请求、配音文本、字幕偏移、镜头时长、章节和发布资料。

建议结构：

```text
scripts/tweakeroo_video/
├── __init__.py
├── storyboard.py     # 镜头、旁白、时长、页码、状态、章节
├── audio.py          # TTS、字幕解析与合并、时长和响度检查
├── video.py          # 静帧动画、转场、合成、字幕烧录、联系表
├── publishing.py     # 标题、简介、标签、章节、置顶评论
├── pipeline.py       # slides / voice / video / cover / publish / all
├── cover.html        # 1600×1000 封面源
└── cover-4x3.html    # 1600×1200 封面源

tests/test_tweakeroo_video.py
build/tweakeroo-video/
```

最终输出：

```text
build/tweakeroo-video/
├── tweakeroo-bilibili.mp4             # 带字幕发布版
├── tweakeroo-bilibili-clean.mp4       # 无字幕干净母版
├── voice-preview.mp3                   # 自然度试听片段
├── tweakeroo-narration.mp3             # 完整独立配音
├── subtitles/tweakeroo.zh-CN.srt       # 独立字幕
├── tweakeroo-cover-1600x1000.png
├── tweakeroo-cover-1600x1000.jpg
├── tweakeroo-cover-1600x1200.png
├── tweakeroo-cover-1600x1200.jpg
├── bilibili-publish.md                 # 完整发布资料
├── final-contact.png                   # 成片联系表
├── slides/                             # 可复查静帧
├── narration/                          # 分镜配音和原始字幕
└── segments/                           # 可复查分镜视频
```

所有大型生成文件留在 `build/tweakeroo-video/`，不提交到 Git。源代码、封面 HTML 和测试纳入版本控制。

## 9. 异常处理与降级

- TTS 服务不可用：保留完整分镜和旁白文本，重试批准的成年男声；不以不符合语气的声音假装完成。
- 指定声音不可用：按 Yunxi → Yunyang → Yunjian 顺序回退，并在发布前记录实际声音。
- 试听片段仍有明显播报腔：先调整断句、删掉书面连接词并恢复默认音高；仍不自然才更换回退声音，不用均衡器或背景音乐掩盖问题。
- 配音超出镜头：优先删掉重复解释或延长对应镜头，不明显加速语音。
- 图片加载失败或尺寸不是 2880×1800：中止构建并报告具体文件，不用模糊占位图继续合成。
- Chrome 或 FFmpeg 编码失败：保留已完成静帧、配音和分镜，命令返回非零状态，禁止生成看似成功的空文件。
- 字体缺失：回退到本机 Noto Sans CJK SC，并在成片静帧中检查中文、英文和数字是否正常显示。
- 响度分析失败：不跳过归一化生成发布版；必须修复分析或音轨后重新输出。

## 10. 测试与验收

### 内容验收

- 五项能力顺序固定，灵魂出窍是第一个正式功能。
- 灵魂出窍明确建议配置顺手快捷键。
- 鞘翅页同时讲自动切换和胸甲交换配置。
- 自动补货完整显示配置、阈值触发和补货完成三个阶段。
- 快速左键与快速右键作为一项连点器能力讲解，并显示多人服务器提示。
- Gamma 明确“不改变真实光照和刷怪规则”。
- 不详细讲 Litematica、MiniHUD、Item Scroller 的能力。
- 标题、封面和旁白没有承诺实际未演示的功能。
- 开头和结尾都出现“把复杂配置翻译成能直接使用的场景”这一账号价值，关注 CTA 不是孤立口号。

### 资产与程序验收

- 十张 2880×1800 原图全部由视频或封面使用，原文件未被修改。
- 所有静帧为 1920×1080，图片默认完整等比显示；局部放大只出现在讲解关键配置时。
- 分镜、章节、字幕和发布资料从同一时间线生成，章节严格递增。
- 每条字幕最多两行，每行不超过约 18 个字符，且不超出成片时长。
- 封面同时生成 1600×1000 和 1600×1200 的 PNG/JPG，缩小后主标题仍能辨认。
- 推荐标题与封面文案不重复，缩小封面后仍能在两秒内识别“别再手动了”和 `Tweakeroo`。

### 成片验收

- `ffprobe` 确认视频为 1920×1080、30 fps、H.264，音频为 AAC。
- 成片时长在 196–205 秒之间。
- 前 8.5 秒出现灵魂出窍、自动补货完成和 Gamma 开启三个清晰结果。
- 无字幕母版、字幕发布版、独立 SRT 和独立配音均存在且非空。
- 语音试听片段与最终配音使用相同声音、语速和音高参数；旁白无连续长句、异常重音或明显新闻播报腔。
- 综合响度约 `-16 LUFS`，真峰值不高于 `-1 dBTP`，无明显削波和长段静音。
- 抽查开场、五个功能、安装和结尾静帧，文字与字幕不遮挡关键配置或实机效果。
- 最终联系表能快速确认全片没有黑帧、破图、构图跳变或字幕越界。

## 11. 成功标准

第一次接触 Tweakeroo 的观众看完后应能够：

1. 记住五项能力分别解决什么麻烦；
2. 知道灵魂出窍、自动补货和 Gamma 的正确边界；
3. 知道从 `X + C` 进入配置并为高频功能设置快捷键；
4. 因为五项清单愿意收藏，并因账号持续提供高质量 Minecraft 模组内容愿意关注；
5. 不会把本视频理解成多人服务器规避规则或自动作弊教程。
