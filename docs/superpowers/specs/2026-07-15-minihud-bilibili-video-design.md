# MiniHUD B 站展示视频设计

**日期：** 2026-07-15

**状态：** 对话设计已确认，待书面复核

## 目标

基于现有 MiniHUD HTML 演示和真实游戏截图，制作一条约 3 分 30 秒的中文 B 站展示视频。视频不按配置菜单逐项讲解，而是围绕六个玩家问题，稳定使用“遇到的问题 → 开什么功能 → 得到什么效果”的表达方式。

成片同时服务两个转化目标：

- **促收藏：** 六个场景组成一张可复用的问题清单，观众以后遇到类似情况能回来查找。
- **促关注：** 结尾明确账号会继续分享实用 Minecraft 模组和生存技巧，不预告“15 种形状演示”等未确定的下一期内容。

内容以用户当前使用的 **Minecraft Java 版 26.2** 和与之匹配的最新 MiniHUD、MaLiLib 为功能基线。场景和核心概念尽量使用跨版本通用的说法，同时明确不同 Minecraft 与 MiniHUD 版本的菜单、功能数量和规则可能不同。

## 受众与语气

- 面向知道 Minecraft 基本操作、但没有系统使用 MiniHUD 的玩家。
- 优先照顾在手机上观看 B 站横屏视频的观众，正文不能依赖小字阅读。
- 文案口语化、可信、直接，不使用“逆天”“必装神模组”等夸张承诺。
- 专有名词只在帮助玩家判断或操作时出现；画面承担功能展示，配音负责解释“为什么有用”。

## 非目标

- 不逐项演示或朗读 15 种形状名称。
- 不制作完整安装教程，只给出正确的安装关系与官方入口提示。
- 不新增游戏截图、第三方图片或 AI 生成的 Minecraft 界面。
- 不把 MiniHUD 描述成自动建造、远程找结构或绕过服务器数据限制的工具。
- 不承诺所有版本拥有完全相同的功能。

## 交付物

1. 1920×1080、30 fps 的 H.264/AAC B 站成片。
2. 无内嵌字幕的干净母版，以及带中文字幕的发布版。
3. 独立的简体中文字幕文件（SRT）。
4. 1600×1000 的 B 站封面 PNG 和 JPG。
5. 发布用标题、简介、标签、章节时间轴和置顶评论建议。
6. 更新后的 MiniHUD HTML 演示及相应自动测试。
7. 可复查的逐页静帧、音频分段和最终联系表。

## 八页演示内容调整

### 第 1 页：结果型开场

- 主标题改为 `一个 MOD，看清隐藏规则`，MiniHUD 作为明确的产品名保留。
- 副标题只保留一个收益句，不再同时陈列五个抽象功能分类。
- 背景继续使用现有形状效果图，但提高可见度，并加入结构边界、圆环或预览的快速切换状态供视频冷开场使用。
- 网页演示仍可显示完整名称；B 站外部封面不直接复用这一帧。

### 第 2 页：问题导航

- 标题改为 `遇到什么问题，就开什么功能`。
- 六张任务卡继续承担网页导航，但每张只保留“问题 + 功能”两层信息。
- 视频中不逐张朗读，只用依次点亮的方式在 14 秒内建立六场景结构。
- 默认 `H` 主渲染开关和 `H + C` 配置入口保留；说明快捷键可以修改。

### 第 3 页：日常信息

- 问题：总在反复打开 F3，或者迷路、施工定位、判断卡顿时找不到关键数字。
- 功能：按任务开启坐标、朝向、群系、目标信息、FPS、延迟或 TPS/MSPT。
- 结果：只留下当前决定需要的几行，减少完整 F3 对画面的遮挡。
- 只使用现有 HUD 图片。视频构图裁近 HUD 区域、弱化暂停菜单，并用局部放大和逐行高亮建立正常游戏中的阅读关系。
- 坐标、朝向等本地信息与联机 TPS/MSPT 分开表述；精确服务器性能数据取决于服务器支持，不能和本地信息作同等承诺。

### 第 4 页：结构边界

- 问题：建筑或结构被水体、山体和地形遮挡，看不清完整范围。
- 功能：在已有结构数据可用时开启结构主边界和组成部分边界。
- 结果：看清结构整体与内部组成，但不会远程寻找结构，也不调用 `/locate`。
- 现有水下结构图片采用裁近、提高边框对比和“关闭 → 开启”遮罩切换，不要求补拍。
- 单人世界可读取本地结构数据；多人服要显示真实结构数据，需要服务器端兼容的 Servux 支持。Carpet 或模糊的“服务器许可”不替代结构数据来源。

### 第 5 页：工程选址

- 问题：建基地、农场或大型工程前，不确定暗区、群系和区块边界是否合适。
- 功能：一次只开启当前问题需要的一层光照、群系、方块网格或区块覆盖。
- 结果：先看见规则，再回到现场处理，避免同时开启大量覆盖层造成误判。
- 现有绿色群系图片降低面填充的视觉压迫，通过边缘强调、局部裁切和前后对比避免被理解成 X-Ray 或渲染故障。
- 文案不把低光照直接等同于必然刷怪；实际生成还受方块、生物、难度和版本规则影响。

### 第 6 页：机制范围

- 问题：信标、刷怪空间或区块机制的有效范围只能靠估算。
- 功能：装置范围看盒状边界，生成和消失距离看球形参考，区块机制看网格或区块覆盖。
- 结果：在施工或选择挂机点前，先确认自己正在判断哪一种规则。
- 现有信标图片保留，通过裁切、提亮信标附近区域、增强边界线和增加少量方向标注解决原图表意不足，不伪造新的游戏 UI。
- `24 / 32 / 128` 只作为常见参考；具体规则仍取决于版本、维度和生物。
- Mob Cap 是生物数量上限，不作为空间范围讲解；可以在基地效率排查中出现。
- 数据来源徽标贴近对应功能，避免把本地、种子和服务器数据混成一条笼统提示。

### 第 7 页：施工规划

- 问题：圆心、半径、占地或高度不容易靠目测确定。
- 功能：使用圆形、圆柱、方框、直线或生成球等施工参考线。
- 结果：开工前先把设计放进世界检查，再决定是否施工。
- 不再以“15 种形状”为视频卖点，也不在结尾预告完整演示。
- 现有圆环图增加圆心、半径和高度三个短标注；只介绍能解决当前问题的代表性形状。
- 统一使用“施工参考线”或“形状参考”，明确不会自动放置或拆除方块。

### 第 8 页：基地管理与收束

- 问题：整理潜影盒、确认目标信息或排查机器效率时，需要频繁打开界面。
- 功能：使用潜影盒、收纳袋、地图或容器/实体物品栏预览，并结合目标信息、Mob Cap、实体和服务器性能信息排查。
- 结果：常见内容先快速确认，出现异常时再沿着现场条件、客户端负载和服务器状态继续检查。
- 默认操作表述为“按住 Shift 悬停预览”，同时说明快捷键和触发方式可以在配置中修改。
- 页面在功能展示后切换为六场景简表，给出 `收藏这份问题清单` 和 `关注我，继续分享实用 Minecraft 模组和生存技巧`。
- 不出现“下一期演示 15 种形状”等承诺。

## 版本、安装与数据口径

- 公开文案写明：本视频以 Minecraft Java 版 26.2 和与其匹配的最新 MiniHUD、MaLiLib 为基线。
- 核心使用思路跨版本通用，但具体功能、名称和规则以对应版本下载页与说明为准。
- 安装关系为 Fabric Loader + 与游戏版本匹配的 MiniHUD 和 MaLiLib；不把 Fabric API 列为 MiniHUD 的固定硬依赖。
- MiniHUD 安装在客户端。Servux 是多人服务器按需安装的数据支持组件，不要求普通观众为单人使用安装。
- 结构边界的多人数据来源明确指向服务器端 Servux 支持。
- 精确 TPS/MSPT 可由 Servux 或 Carpet 等服务器支持提供；没有同步时可能是估算或不可用。
- 参考点距离只有在玩家先设置参考点后才有意义。
- 史莱姆区块等种子相关功能需要正确种子；覆盖层显示规则，不保证现场满足所有生成条件。

## 封面设计

- 输出比例为 1600×1000，另保留 1920×1080 的视频首帧版本。
- 使用现有工程圆环或边界截图作为主视觉，结构边界作为小面积辅助，不拼入三张以上图片。
- 主标题固定为两行：`一个 MOD` / `看清隐藏规则`。
- 辅助标签为 `MiniHUD · 6 个实用场景`。
- 标题使用白色、青色和黄色高对比组合；背景压暗但不能让真实效果消失。
- 关键边界允许加发光描边、箭头和局部放大，不伪造游戏中不存在的功能效果。
- 封面不堆安装版本、作者信息和完整功能清单；这些内容进入简介。

## 配音、字幕与声音

- 配音为自然、偏低沉的成年中文男声，保持讲解感，不使用过度播音腔或夸张情绪。
- 优先试用 `zh-CN-YunyangNeural`，语速约 `-4%`、音高约 `-4Hz`；若环境不可用，使用 `zh-CN-YunjianNeural` 并保持相同节奏目标。
- 全稿控制在约 750–850 个汉字，通过停顿而不是大幅降速达到 3 分 30 秒。
- 每一场景的口播固定回答三个问题：玩家遇到什么、打开什么、画面会怎样变化。
- 字幕每屏最多两行，关键句优先单行；1080p 发布版字号不低于 42 px，并避开 B 站播放器底部控件安全区。
- 同时交付烧录字幕版和独立 SRT，字幕按实际音频时间生成，不靠平均分配时长。
- 不引入来源不明的背景音乐。默认以清晰人声、轻量转场点击和低强度提示音完成声音设计。
- 最终人声按约 -16 LUFS 综合响度、-1 dBTP 峰值控制，避免手机外放忽大忽小。

## 发布文案策略

- 标题突出“问题解决”和“收藏价值”，不把版本号放在标题最前面。
- 简介第一段用两句话说明视频解决的六类问题。
- 简介列出 Minecraft 26.2 基线、MiniHUD、MaLiLib、Fabric Loader，以及官方 GitHub、Modrinth 或 CurseForge 入口。
- 简介明确跨版本差异和多人服务器数据限制。
- 标签覆盖 `Minecraft`、`我的世界`、`MiniHUD`、`Fabric`、`生存技巧`、`模组推荐`，避免与内容无关的泛流量标签。
- 置顶评论提供六场景文字索引和章节时间，继续强化收藏价值。

## 制作流程与文件边界

1. 修改 `source/extra/MOD介绍/minihud/index.html` 的标题、场景文案、视频导出状态和收束页。
2. 同步修改 `source/MOD介绍/minihud/minihud.rst` 的版本、安装和多人数据说明。
3. 更新静态测试和浏览器测试，补充活动页元素边界检查，避免移动端“页面宽度没超出但内容被裁切”的漏检。
4. 以 1920×1080 导出每页及必要交互状态的无导航静帧。
5. 使用现有图片的裁切、缩放、遮罩、标注和前后对比生成镜头；不修改原始截图文件。
6. 按场景生成独立配音，依据真实音频长度制作镜头和 SRT。
7. 合成干净母版、字幕发布版、封面和发布文案。
8. 输出到 `build/minihud-video/`，源演示和测试仍保留在现有目录结构中。

## 异常与降级

- 现有 HUD 图片包含暂停菜单：只裁切和弱化菜单区域，不声称拥有未录制的无菜单素材。
- 信标边界在原图中不清楚：使用真实截图上的裁切、对比度、描边和说明标注，不生成虚假游戏画面。
- TTS 服务暂时不可用：保留分段脚本并重试指定男声，不用其他性别或明显不同风格的声音直接替代成片。
- 字体缺失：使用本机可商用的中文无衬线字体回退，并在导出前检查所有汉字是否正常显示。
- 某个交互状态不适合线性视频：改用同页静帧加高亮，不把网页按钮操作完整录入成片。
- 时长超出目标：优先删减重复清单和停顿，不通过明显加速男声压缩时长。

## 成功标准

最终视频应让第一次接触 MiniHUD 的玩家在看完后能够：

1. 用六类常见问题判断自己该寻找哪组功能；
2. 理解 MiniHUD 是把信息和规则画出来，而不是自动完成任务；
3. 知道 26.2、旧版本和多人服务器之间可能存在功能与数据差异；
4. 因为六场景清单愿意收藏，并因为账号持续提供实用 Minecraft 内容而愿意关注。
