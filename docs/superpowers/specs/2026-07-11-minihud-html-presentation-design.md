# MiniHUD HTML PPT 设计规格

## 目标

为 8–18 岁的 Minecraft 玩家制作一份可在网站中自行翻阅的中文 HTML PPT。内容以 MiniHUD 官方功能和用户导出的实际配置为依据，覆盖主要用户能力，但不展示源码、类名、内部实现或配置字段。讲解深度来自玩家任务、场景组合、空间机制和多人游戏限制，而不是技术实现。

最终内容必须回答三个问题：

1. 玩家遇到某个问题时，MiniHUD 哪一类功能能帮助他？
2. 开启功能后，画面中的信息或边界代表什么？
3. 哪些结果依赖世界种子、单人世界数据或服务器同步，不能盲目相信？

## 依据与版本口径

- 官方项目：`https://github.com/maruohon/minihud`
- 当前内容核对基线：官方 `pre-rewrite/fabric/1.21.1-masa` 分支，提交 `faebd93e39e4464294d55d3e18c248397c2ca0eb`。
- 官方仓库默认分支是 1.12.2 系列，因此不能只根据默认分支整理当前功能；默认分支仅用于核对长期存在的核心能力。
- 页面不承诺“所有 Minecraft 版本功能完全相同”。安装页明确提示玩家按自己的 Minecraft 版本选择 MiniHUD 与 MaLiLib，并以对应下载页说明为准。
- 现有 Item Scroller 演示 `source/extra/MOD介绍/itemscroller/index.html` 是同系列的视觉和交互基准。
- 场景画面以用户导出的 `C:\Users\zhaojd5\AppData\Roaming\PrismLauncher\instances\26.2\minecraft\config\minihud.json` 为本地配置依据：沿用其中的结构、范围和形状配色，核对可用功能与快捷键。配置字段和值只在制作和校验时使用，不直接堆在面向学生的正文中。

## 内容原则

- **场景优先：** 标题使用“我想知道 / 我想检查 / 我想规划”，而不是配置菜单名称。
- **任务牵引：** 六个场景组成“日常游玩 → 外出探索 → 工程选址 → 机制规划 → 开始施工 → 完工排查”的玩家任务链；具体结构或装置只作为例子，不占据场景标题。
- **分类完整：** 每项主要用户能力都进入分类矩阵；不把几十个信息行逐个拆成幻灯片。
- **由浅入深：** 每页先给 8 岁读者能理解的一句话，再给 12–18 岁读者可继续阅读的判断方法和限制。
- **不夸大能力：** MiniHUD 只显示信息和覆盖层，不自动建造、不修改方块，也不能绕过服务器缺少的数据。
- **少而有效：** 强调按任务开启功能，避免同时开启大量信息行和覆盖层。

## 功能分类矩阵

### A. 信息 HUD：随时读懂玩家与世界

面向“我不想一直打开完整 F3”的需求，按用途合并展示：

- 导航定位：坐标、缩放坐标、朝向、俯仰与旋转角度、维度、区块坐标、区块内坐标、参考点距离。
- 行动状态：移动速度、分轴速度、水平/垂直速度、疾跑状态、方块破坏速度。
- 世界环境：群系、天气、世界时间、现实时间、光照、难度。
- 注视目标：目标方块坐标与属性、目标实体名称/生命值/状态效果。
- 生物与物件细节：蜂巢蜜蜂数和蜂蜜等级、熔炉经验、僵尸村民转化、马匹速度和跳跃、熊猫基因等适用信息。
- 性能与联机：FPS、内存、实体/方块实体/粒子数量、已加载区块、区块更新、延迟、TPS/MSPT、Mob Cap 与 Servux 状态。

PPT 不逐项解释菜单，而是提供“探索组合、建筑组合、性能排查组合”三套推荐显示方案。

### B. 环境与网格：检查脚下和周围

面向“哪里需要处理”的需求：

- 光照等级覆盖：用数字或标记识别可能刷怪的暗区，并说明不同游戏版本规则可能不同。
- 方块网格与原版区块边界：用于精确对齐、测量和定位区块内位置。
- 生物群系边界：用于寻找群系交界和规划对群系敏感的工程。
- 区域文件边界：作为大尺度世界分区参考，放在进阶说明中。
- 出生区块与可生成列高度等覆盖：用于技术生存规划，明确版本机制差异。
- 原版调试覆盖层：碰撞箱、相邻更新、固体面、水体等统一归为“高级诊断”，不作为低龄读者的主线操作。

### C. 范围与边界：看见原本不可见的规则

面向“这个装置或区域到底影响多远”的需求：

- 信标范围与潮涌核心范围。
- 史莱姆区块、出生区块与随机刻区域。
- 生物可生成、可消失和彻底消失的距离范围。
- 结构主边界与组成部分边界；支持的具体结构不在主页面堆满名称，用“村庄、要塞、堡垒、古城、试炼密室等”举例。
- 村民交易信息覆盖，帮助筛选附魔书交易；归入“实体范围与信息”分组。

这一类必须显著显示数据徽标：`本地可用`、`需要种子`、`需要服务器数据`。结构、Mob Cap、精确 TPS 等内容在多人服上可能需要 Servux、Carpet 或服务器许可。

### D. 建筑与形状：把计划画在世界里

面向“我想先标范围再施工”的需求：

- 方框：标出两角、占地、挖掘区和建筑外框。
- 圆 / 圆柱：设置中心、半径、高度和主轴。
- 方块线：连接两个坐标，辅助路线、轴线和测距。
- 方块球体：辅助球形建筑。
- 可调生成球，以及 24、32、128 格等生物生成/消失参考球。
- 形状管理：启用、选择、移动到玩家位置、修改颜色与显示方式。

讲解明确形状是视觉参考，不会自动放置或拆除方块。

### E. 预览与快速检查：少开容器，先看内容

面向“我只想快速确认里面是什么”的需求：

- 地图预览。
- 潜影盒内容预览。
- 支持时的容器或实体物品栏预览。
- 蜜蜂、六角恐龙等物品提示信息。

这类功能作为一组完整呈现，避免在现有“空间覆盖层”叙事中被遗漏。

## 八页信息架构

### 第 1 页：封面

- 标题：`MiniHUD`
- 副标题：`把看不见的信息、边界与范围画出来`
- 五类能力徽标：信息、环境、范围、形状、预览。
- 保留 Item Scroller 的翻页提示和系列视觉。
- 页脚给出 MiniHUD + MaLiLib 的版本匹配提醒和官方入口，避免占用一个场景页。

### 第 2 页：任务地图

- 用一条清晰的玩家任务链连接六个场景：日常游玩 → 外出探索 → 工程选址 → 机制规划 → 开始施工 → 完工排查。
- 每个节点只保留一个动词、一句问题和一个醒目的场景图标；点击节点可查看该场景会用到的 MiniHUD 能力。
- 用“小地图路线”而不是功能矩阵作为全篇导航，让低龄读者先知道自己正在解决什么问题。
- 页尾给出用户实际配置入口 `H` 和 `H + C`，并提示快捷键可以修改。

### 第 3 页：场景一——日常游玩，随时掌握信息

- 左侧为简化游戏画面，右上角/左上角显示轻量信息 HUD，画面风格参考用户实际配置。
- 提供“出门探索、准备施工、卡顿排查”三种一键示意组合，分别展示位置与方向、方块与区块、FPS 与 TPS/MSPT 等信息。
- 熊猫基因、蜂巢、马匹和目标实体等细节作为“遇到特定对象时再开”的趣味彩蛋，不占主线。
- 核心判断：只保留当前任务需要的信息，避免把屏幕变成另一张 F3。

### 第 4 页：场景二——外出探索，看清结构

- 主视觉是一片被树木和地形遮挡的探索区域；切换后出现结构主边界和组成部分边界，让玩家看懂“结构在哪里、由哪些部分组成”。
- 林地府邸作为主画面案例，另以小标签举例要塞、试炼密室、海底神殿、村庄等；场景标题不直接使用某个结构名称。
- 明确能力边界：MiniHUD 不是远程结构搜索器，不调用 `/locate`；需要玩家探索到相应区域并获得可用的结构数据。
- 使用短步骤表达：到达附近 → 数据可用 → 开启结构显示 → 观察边界 → 关闭后继续游玩。

### 第 5 页：场景三——工程选址，检查周围环境

- 用光照标记、方块网格、区块边界、群系边界、史莱姆区块和可生成列高度回答“这里适不适合建”。
- 主画面支持“普通地面 / 打开检查层”的前后切换，颜色和线框出现后，旁边只解释玩家下一步应该观察什么。
- 进阶面板收纳区域文件、出生区块和高级诊断覆盖层，避免主画面变成覆盖层清单。
- 误区：覆盖层只把规则画出来，不会替玩家照明、清场或选择最终位置。

### 第 6 页：场景四——机制规划，确认影响范围

- 以信标分层范围为主视觉，补充潮涌核心、避雷针、随机刻区域、生成/消失距离球和出生区块等不可见边界。
- 点击不同任务标签后，主画面从装置立方范围切换到区块范围或球形范围，让学生建立“不同规则使用不同形状”的认识。
- 24 / 32 / 128 格只作为常见参考，具体判断仍要结合版本、维度和生物规则。
- 数据来源徽标贴在具体任务旁，不单独制作服务器配置页。

### 第 7 页：场景五——开始施工，把设计画进世界

- 用一座圆形刷怪塔作为主案例，但标题仍聚焦“规划建筑与空间”。
- 方框负责占地与挖掘区，圆/圆柱负责塔身和平面半径，方块线负责中心轴与路线，球体负责球形建筑和空间高度参考。
- 通过可点击的平面图/侧视图切换，说明同一个工程如何从占地、半径、楼层高度和挂机位置四个角度检查。
- 强调形状只是视觉参考，不自动放置或拆除方块。

### 第 8 页：场景六——完工排查，快速找到问题

- 用“为什么效率不对？”作为入口，把 Mob Cap、TPS/MSPT、实体数量、光照、随机刻、目标方块和目标实体信息组织成一条排查路径。
- 把地图、潜影盒、容器/实体物品栏预览和村民交易信息放入“少开界面，快速确认”小区域，补齐快速查看能力但不抢主线。
- 数据来源提示嵌入相关步骤：本地可见、需要正确种子、需要 Servux/Carpet 或服务器许可。
- 页尾给出显示问题顺序：总开关 → 当前场景功能 → 数据来源 → 距离与维度 → 快捷键冲突 → 服务器规则。

## 视觉与交互设计

### 系列继承

- 延续 Item Scroller 的深色高对比全屏画布、彩色章节、圆角玻璃卡片和渐变大标题。
- 延续键盘方向键、空格、鼠标滚轮、点击、触摸滑动和底部圆点导航。
- 延续移动端重排、视频导出参数和减少动态效果支持。

### MiniHUD 专属表达

- 背景使用低对比坐标网格和区块线，不使用高噪声像素装饰。
- 主色为青色与蓝色；光照用黄/红、范围用紫/玫红、建筑用青绿，颜色同时配文字标签，不能只靠颜色区分。
- 结构、信标范围和形状的示意色优先采用用户 `minihud.json` 中的实际颜色；页面可以提高不透明度以保证投影和小屏可读，但保持色相关系。
- 使用 CSS/SVG 风格的区块、球体、边界和光照示意；视觉效果服务于机制理解。
- 不放置无法播放的 OBS 视频按钮。没有实机视频时，使用页面内动态示意；将来有视频可沿用 Item Scroller 的弹窗播放器接入。

### 8–18 岁视觉语言

- 每页只保留一个任务句、一个主画面和最多三个判断步骤；详细清单进入“再深入一点”面板。
- 场景标题使用动词短句，例如“看清结构”“检查周围”“画出计划”，避免直接使用内部分类名。
- 画面采用类似 Minecraft 任务面板的清晰层级：大号场景编号、简短任务目标、前后对比和即时反馈；不用幼儿化卡通，也不使用密集参数表。
- 关键动作可点击切换，切换结果在主画面中立刻发生；动画保持短、稳、可关闭，不让效果盖过信息。

### 自助阅读深度

- 每页默认只显示结论和核心分类。
- `再深入一点` 按钮打开页内详情面板，包含判断方法、数据来源和误区；按 Escape 或关闭按钮返回。
- 详情面板不能改变幻灯片页数，保证“八页”约束。
- 交互按钮有清晰焦点样式、键盘操作和 ARIA 标签。

## 文件边界

- 修改：`source/extra/MOD介绍/minihud/index.html`——完整的独立 HTML PPT、样式、交互和示意动画。
- 修改：`source/MOD介绍/minihud/minihud.rst`——页面入口、五类功能摘要、多人服限制和官方链接。
- 保留：`source/MOD介绍/index.rst` 中现有的 MiniHUD 导航项，不覆盖其他未提交改动。
- 可选素材：从官方仓库提取的项目图标只能作为本地静态素材使用，并保留项目归属；不把临时克隆目录提交到本站仓库。

## 异常与降级

- 页面不依赖 Google Fonts、CDN 或在线脚本，离线打开仍可使用。
- 不存在视频文件时不显示失效播放按钮。
- CSS 动画关闭或系统启用 `prefers-reduced-motion` 时，内容仍完整可读。
- 窄屏改为单列并允许页内纵向滚动；导航不会遮挡正文。
- JavaScript 只负责翻页、详情面板和示意切换，正文语义保留在 HTML 中。

## 验收标准

1. 幻灯片总数严格为 8 页。
2. 功能矩阵 A–E 的每个项目都能映射到六个用户场景或进阶说明中的至少一处。
3. 使用说明以用户问题和任务开头，不以源码、类名或配置字段开头。
4. 不出现“所有功能在多人服都可用”“所有版本规则相同”等误导性表述。
5. 默认快捷键、MaLiLib 依赖和数据来源说明与官方功能口径一致。
6. 键盘、鼠标、触摸和底部导航均可翻页；详情面板可通过键盘关闭。
7. 1366×768、1920×1080、常见手机宽度下无关键文字截断。
8. 不覆盖 Item Scroller 文件或用户现有的无关改动。
9. Sphinx 构建能复制并链接 MiniHUD HTML，入口可从 MOD 介绍页打开。
10. 主页面不显示原始配置字段名；结构、范围、形状的视觉色相与用户导出的 `minihud.json` 保持一致。

## 验证方法

- 用功能覆盖表逐项对照官方 1.21.1 分支中的公开信息行、渲染器、形状与预览能力。
- 搜索成品中是否出现 Java 类名、源码路径、旧版独占机制或未解释的英文配置字段。
- 使用浏览器自动化检查 8 页导航、键盘操作、详情面板、移动端布局和控制台错误。
- 运行 Sphinx HTML 构建并检查 MiniHUD 页面和独立演示的最终路径。
