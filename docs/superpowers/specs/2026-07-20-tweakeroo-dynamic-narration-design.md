# Tweakeroo 动态口语配音补充设计

**日期：** 2026-07-20

**状态：** 克制口语型已确认，待书面复核

## 1. 问题与目标

现有试听使用 `zh-CN-YunxiNeural`，音色方向可以保留，但每个分镜整段只调用一次 TTS，且所有内容固定使用 `-2%` 语速和 `0Hz` 音高。结果是冷开场、普通讲解和 Gamma 笑点共享同一种节奏，长句只能依赖 TTS 自行断句，听感匀速、缺少重音，AI 感明显。

本轮只重做约 25 秒试听，不生成完整配音和视频。目标是保留清楚、克制的教程口吻，同时让语速、停顿和句尾走向随语义变化，听起来像真人在讲，而不是激情播音或刻意表演。

## 2. 已确认方向

采用用户选择的 **克制口语型**：

- 保留云希男声，不因节奏问题先换音色；
- 开场短句略快、轻微抬调，迅速抓住注意力；
- 普通说明保持接近日常说话的中速，只做小幅快慢变化；
- 提醒和笑点先留出呼吸，再稍慢、轻微降调；
- 不用全段后期变速、夸张升降调或背景音乐掩盖机械感。

不采用“活泼主播型”。本视频以高质量教程和可信感吸粉，过强的激情讲解会削弱内容气质，也更容易产生另一种合成腔。

## 3. 试听结构与表达曲线

试听仍使用三个已选分镜，便于与首版直接对比：

| 内容 | 表达目的 | 语速/音高方向 | 句后停顿 |
| --- | --- | --- | --- |
| “灵魂出窍。” | 冷开场钩子 | 约 `+6%`、`+2Hz`，短促但不喊 | 约 180 ms |
| 灵魂出窍效果说明 | 正常教程口语 | 约 `+1%` 到 `-2%` 小幅变化，动作词稍快，结论句回落 | 140–280 ms |
| Gamma 提醒与笑点 | 先给结果，再反转提醒 | 结果句中性；“不过”前停顿；包袱约 `-4%`、`-2Hz` | 180–360 ms |

长分镜按语义拆为多个短句分别生成。例如 Gamma 不再整段朗读，而按“开启后的效果 → 不过 → 矿洞是亮了 → 刷怪规则没有改变 → 火把仍要插”形成表达曲线。停顿长度按语义设定，不使用相同的固定间隔。

试听目标时长为 20–27 秒。短句不能为了追求起伏而切得零碎；同一个完整意思仍应保持在一个自然呼吸内。

## 4. 数据结构与生成流程

新增短句级配音单元 `VoicePart`，至少包含：

- `text`：交给 TTS 的口语短句；
- `rate`：本短句语速；
- `pitch`：本短句音高；
- `pause_ms`：本短句结束后的静音长度。

每个分镜由一个或多个 `VoicePart` 组成。生成流程为：

1. 按短句分别调用 Edge TTS，继续使用 Yunxi 和现有三次有限重试；
2. 保留每个短句生成的 MP3 与 SRT；
3. 用 FFmpeg 顺序拼接短句，并在短句之间插入指定静音；
4. 按实际音频时长和插入停顿偏移短句字幕；
5. 合并为现有分镜级 MP3/SRT，使后续完整时间线接口不变；
6. 把三个试听分镜拼为新版动态试听文件。

分镜、视频和发布资料仍以 `storyboard.py` 为单一事实来源。动态表达配置只描述“怎么说”，不复制镜头时长、章节或画面状态。

## 5. 字幕、时长与异常处理

- 字幕文本与实际朗读短句一一对应，停顿期间不提前显示下一句；
- 最终字幕继续遵守每行最多 18 字、每屏最多两行；
- 每个分镜配音仍不得超出其可用镜头时长，并保留合理尾部呼吸；
- 单个短句 TTS 失败时只重试该短句，三次失败后中止，不生成伪成功试听；
- FFmpeg 拼接失败时保留已经生成的短句文件，便于定位具体问题；
- 如果动态版仍机械，优先调整分句和文字口语度，不继续叠加更大的音高变化。

## 6. 测试与验收

自动化测试覆盖：

- 三类表达至少使用两种不同语速，并包含轻微升调和降调；
- 停顿长度不全部相同，且保持在自然口语范围；
- 长分镜被拆成多个真实 TTS 调用，而非整段一次生成；
- 合并字幕包含正确的短句偏移，顺序正确、无重叠；
- TTS 有限重试、镜头时长、字幕宽度等现有保护不回退；
- 旧版完整配音和视频接口保持兼容。

人工试听通过标准：

1. “灵魂出窍”像开场点题，不拖沓也不喊；
2. 普通说明能听出动作、用途和结论的层次，不是逐字匀速念稿；
3. Gamma 的“不过”有转折停顿，笑点自然落下，不故意挤眉弄眼；
4. 没有突兀变声、句间断裂、尾字吞音或明显新闻播报腔；
5. 用户确认新版试听后，才将同一表达规则扩展到全部 20 个分镜。
